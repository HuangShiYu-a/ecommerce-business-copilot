## 0. 背景与结论摘要

P0~P7 已完成（`75c2e4a`/`817d778`）。P8 前的三轮审查（含源码级核验）确认以下评测层问题**真实存在**，均已在代码中定论：

- **M1** `multi_tool` 判定过宽：gold 8 例全要求"两个独立任务"，但 `judge_m1_plan` 只查 `C∩R≠∅ ∧ C⊆A`（漏调可过）；
- **M5** CLI 路径无预热（`run_live_all` 有预热但未被 CLI 调用；`graph_factory` 惰性建图 → P95 可能含冷启动样本）；
- **M8** 对比不可比：legacy 18/22（1×、`facts_on=False`、只算支持集）vs ReAct 78/78（26×3、全量 M2 谓词）；
- **M3** `required_facts` 未参与判定（gold 注释"答案含 facts"与实际不符）；
- **M2** 谓词范围边界（UNDETERMINED=错误码即未定、OP-07=冒烟）未文档化；
- **元数据**：报告 `git_commit` 记的是运行时的最后提交（P4 报告记 cd5ed7c），无法证明对应实际运行代码（P1~P6 未提交改动之上运行）。

**三条原则**（用户拍板）：
1. **不改业务 Runtime**，只修评测层与文档层（除非发现必须修复的实际业务缺陷）；
2. **不预设重跑后的数字保持不变**，以新结果为准；
3. **不因等待 P8 暂停投递**——但用户已决定**今天修完 + 简历定稿后再投**。

**决策 1（M3/M2）**：选 **方案 A**——明确指标边界，不强行扩张判定范围（M3 测"条件编排"，M2 测"业务任务完成"）；**保留数字的前提 = 判定逻辑与 Gold 经审查仍成立**，审查发现错误必须修正，不以保数为目的。
**决策 2**：P8 在独立分支 **`p8-eval-calibration`** 实施，完成后合回 main。

## 3. 分阶段实施规划（每阶段核查评估 + 门禁）

> 顺序原则：代码修复（A-C）→ 审查与文档（D）→ 提交+官方重跑（E）→ 文档/简历同步（F）→ 收尾（G）。**E 必须在 A-D 全部完成后**，保证官方报告覆盖最终代码状态。

| 阶段 | 实施项 | 核查/评估 | 门禁（Pass 标准） |
|---|---|---|---|
| **A M1 判定修复** | I1 | `test_eval_judgments` 全过（含 3 新负向单测）；offline Phase A（M1 45/45 应仍 100%——fake 预设全调）；确认 boundary/clarify/no_tool 语义未破 | 单测绿 + offline 100% |
| **B 预热修复 + M1 严格重跑** | I2 + I3 | 预热日志确认三模式建图；M1 live 45×3 出严格口径数字（预览）；报告含逐用例明细 | 新 M1 数字落定 + 报告结构含明细 |
| **C M8 同口径重算** | I4 | baseline 改造单测/导入；`_latest_report` 校验逻辑测试；M8 预览重跑（22×3） | 可比数字（coverage 两维 + 共同子集业务通过率）+ 指标改名 |
| **D M3/M2 边界 + Gold 审查** | I5 + I6 + I9 | 文档-代码一致性核对（gold 注释 ↔ judge 实际行为）；审查记录（每个 gold/谓词的核查结论）；冻结项清单（若有→上报） | 文档一致 + 审查记录完整 + 冻结项已上报待用户定 |
| **E 元数据 + 提交 + 官方全量重跑** | I7 + I8 | `git log` 确认 P8 提交在前；官方全量 live（M1 严格/M2/M3/M4 + M8）出最终数字；新报告 metadata 含完整 SHA + clean；旧报告标历史 | **报告可追溯到 P8 commit + 工作树干净** + 最终数字落定 |
| **F 文档/README/简历同步** | I10 + I11 | README↔报告↔评估计划↔简历数字逐项核对（自动化脚本比对） | 一致性核对全过；简历文案交付用户排版 |
| **G 收尾** | I12 | 远端可见；main 合并 | GitHub 页面就绪 |
